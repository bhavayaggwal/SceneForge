## 2. Decision: SceneForge = "Talk to a place"

Drop in any 3D splat capture (`.ply`/`.spz`). A **local** AI finds objects, counts, measures, answers questions, flies the camera to the answer and pins it in 3D. It can later be exposed as an **MCP server** so any agent can query 3D captures.

Example questions:
- "Where's the fire extinguisher?"
- "Will a 2.1 m sofa fit on that wall?"
- "List everything in this room."

### Architecture (adapted for a small local model): index once, answer many
1. **Scan:** auto-render 24–48 views around the scene.
2. **Detect:** Qwen3-VL returns `bbox_2d` (0–1000 normalized). A raycast from each box centre gives a 3D point. Merge sightings across views into an object index (label, position, sightings).
3. **Answer:** the model only classifies intent (find / count / measure / describe) via a JSON schema. Code queries the index, measures with real geometry, then calls `fly_to` and places a pin.
4. **Scale calibration:** one click on a known length (e.g., a door), because splats from video have no metric scale.

**Simplification:** the main app no longer needs the Python backend, torch, COLMAP, Celery, or the depth estimator. Stack: **Next.js + Ollama**. The old FastAPI pipeline is superseded.

## 6. Risks
- **VLM speed on Pascal:** unmeasured; estimated 10–30 s per view, so 8–24 min to index a scene. Index in the background.
- **VRAM contention (model + viewer):** pause rendering during inference; fall back to the 2B model.
- **4B box accuracy:** merge across views; Grounding DINO as backup.
- **No metric scale:** one-click calibration.
- **Brush/COLMAP speed on the P2000:** unmeasured; only needed for own captures.
